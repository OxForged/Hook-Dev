A Latch is a hook contract attached to a liquidity pool. Attach one, and a share of every swap flows exactly where you point it — to the people providing liquidity, to a roster you choose, to the holders of your token. Nothing else in the protocol touches that money.

What a Latch is

Three things to know before one sits in your swap path.

The mechanism is small enough to hold in your head. That is deliberate.

Custody sits in one place.

The Vault custodies every token; pool managers hold nothing. registerApp is irreversible — once an app can move funds against the Vault, it always can — so it sits behind a multisig and a timelock, never an EOA.

bits 0 · 7 · 11 = RevShareHook

A Latch declares what it does.

Every Latch answers getHooksRegistrationBitmap() with a 14-bit map over the pool callbacks. The LatchRegistry reads that map, classifies it, and lists it. A listing is what the bitmap says — it is not an audit.

48hcustody
6hpolicy

Two clocks on governance.

Anything that touches custody — the Vault, the pool managers — waits 48 hours behind a timelock. Fee policy, set by a replaceable controller, waits six. Both are long enough to read the transaction before it lands.

Step 1

Install the SDK and read the registry.

The SDK is MIT-licensed and independently authored, so building against Latch never pulls GPL code into your project. Your first read is a single view call.

terminal · then read.ts
$ npm install @latchprotocol/sdk viem

import { createPublicClient, http, parseAbi } from 'viem'
import { sepolia } from 'viem/chains'

// LatchRegistry on Ethereum Sepolia — the only live deployment today
const REGISTRY = '0xB504da43C6ED342a511f3e5849f53035F2C807d1'

const client = createPublicClient({ chain: sepolia, transport: http() })
const count = await client.readContract({
  address: REGISTRY,
  abi: parseAbi(['function latchCount() view returns (uint256)']),
  functionName: 'latchCount',
})

Step 2

Write the Latch. Declare only the callbacks you use.

The bitmap is the contract's promise to the pool. RevShareHook needs three bits: it validates at initialize, and it takes its delta after the swap — so it never sits in front of one.

src/MyLatch.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

import { BaseCLHook } from "@latchprotocol/hooks/BaseCLHook.sol";

contract MyLatch is BaseCLHook {
    /// The registry reads this bitmap by calling it on the Latch itself.
    function getHooksRegistrationBitmap() public pure override returns (uint16) {
        return BEFORE_INITIALIZE | AFTER_SWAP | AFTER_SWAP_RETURNS_DELTA;
    }

    function _afterSwap(/* … */) internal override returns (bytes4, int128 hookDelta) {
        // take the fee here; bit 11 requires bit 7 and the base contract re-checks it
    }
}

Step 3

Configure the split. It must sum to 10 000.

Four numbers per pool. The highlighted values are bound to the handles in the hero — drag them and this call changes with you. Anything that does not sum to SPLIT_DENOMINATOR reverts.

script/Configure.s.sol
latch.configure(key, RevShareHook.ConfigParams({
    feePips:        3_000,   // of PIPS_DENOMINATOR = 1_000_000, cap 100_000
    lpDonateBps:    6_000,   // back to the pool's LPs
    beneficiaryBps: 2_500,   // weighted roster, max 8
    distributorBps: 1_500    // epoch distributor for token holders
}));
// lpDonateBps + beneficiaryBps + distributorBps == SPLIT_DENOMINATOR (10_000)

Step 4

Attach it to a pool, then list it.

The pool key names the Latch; initializing the pool validates the bitmap against the contract. Registering makes it discoverable in the marketplace, with its capabilities read straight from chain.

script/Deploy.s.sol
PoolKey memory key = PoolKey({
    currency0:   ltUSD,
    currency1:   ltETH,
    hooks:       IHooks(address(latch)),   // the Latch, attached
    poolManager: poolManager,
    fee:         lpFee,
    parameters:  params
});
poolManager.initialize(key, sqrtPriceX96);   // validates the bitmap

registry.register(address(latch), metadata);  // now it is a listing
